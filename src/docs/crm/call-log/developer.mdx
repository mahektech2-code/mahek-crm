The Call Log is a **pure engine** (`buildQueue`) fed by **one service** (`queue-service.ts`) and **settled once a day** into `queue_snapshots`. The screen renders what the service returns; saving a call goes through `saveInteraction`, which ends by computing and **storing** the next-step sentence on the call. Every code block below is cut from the source this deployment was built from.

## Saving a call

`saveInteraction` (`lib/services/interaction-service.ts`) validates outside the transaction, then writes **everything in one transaction**: the order (`pending_approval`), reminders from the outcome and next actions, the complaint, the `calls` row, opportunities, timeline events, product lines, and the customer's `last_call_date` / `last_contact_date` / `last_order_date` / `do_not_contact`. Recomputes (buying cycle, inactivity, outstanding, follow-up state) run after commit.

An `idempotency_key` that already exists returns the **stored** next step and *Already logged* — a double-click cannot show a second answer.

<Callout kind="warn" title="Never let a recompute touch these">
`lib/recompute.ts` must not learn to rebuild the `next_step_*` columns. A cache answers "when is the next call" and is rebuilt when the answer changes; these answer "what did we tell the person who logged this call, on that day", and rebuilding them destroys the question. Same kind of mark as `orders.approved_at`.
</Callout>

## Changing the Call Log safely

<Steps>
<Step title="Put the rule in the engine, and only there">
A new reason, window or suppression belongs in `engines/queue.ts`. `next-step.ts` re-asks `buildQueue`, so the "comes back on" sentence follows automatically — never re-derive a rule in a second place.
</Step>
<Step title="Make every threshold a setting">
Add the key to `registry.ts` (with a `Config` type entry), read it through `QueueConfig`. No number a manager might change is a constant.
</Step>
<Step title="Suppress, never drop">
Anything that keeps a customer off the list must return a sentence for the held-back strip.
</Step>
<Step title="Give a new reason kind everything it needs">
A weight in `DEFAULT_TIER_WEIGHTS`, a tone in `REASON_TONE` (queue-screen), a short name in `REASON_BADGE` (call panel), wording in `describe()` (next-step), and a filter pill if it is one.
</Step>
<Step title="Test it in engines.test.ts first">
The engine is pure; a rule without a test is a rule nobody can tell has broken.
</Step>
</Steps>

| Only outbound answered calls start the outcome cooldown | `queueInputs`, `lastAnsweredOutcome` |
