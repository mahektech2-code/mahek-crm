The EOD Report is a server page over **one metrics function**, `eodMetricsForRange`, whose output feeds a pure engine that turns it into table lines and a WhatsApp message. Submitting is one action that re-checks the reminder gate and upserts `eod_reports`; a nightly step writes reports for anybody who did not. The same metrics function feeds the Dashboard, which is where the span-before comparison lives. Everything below is cut from the source this deployment was built from.

## Permissions

<CapabilityGrid names={["team.report", "reminder.close"]} />

- <ModuleRef k="crm.eod" /> guards the route.
- `teamEod` itself asks `requireCapability("team.report")`; the page asks the same capability **and** `managesHere(user, "crm")` first, so a person holding `team.report` through another app is not drawn a team of one and the page never crashes on the refusal.
- `submitEod` runs `resolveScope()` and re-checks `eodPreflightFor` server-side.

## Changing it safely

<Steps>
<Step title="Add a figure to eodMetricsForRange and nowhere else">
The Dashboard and the team table read it for free. A second query for "the same number" is how two screens come to disagree.
</Step>
<Step title="Count sales with orderCountsSql">
Replace a status literal list with `orderCountsSql("o")` and value with `orderValueSql("o")` when touching these subqueries.
</Step>
<Step title="Keep the message pure">
WhatsApp formatting lives in `aggregateEod`. Test it there; short lines, no tables.
</Step>
<Step title="Never overwrite a submitted report from a job">
`autoGenerateEodReports` checks `storedEodReport` first. Keep it that way.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| Approved orders counted as `status in ('captured','confirmed','dispatched')`, missing `in_transit` and `delivered` from `PURCHASE_STATUSES` | `eod-service.ts` `eodMetricsForRange` (`orders_count`, `orders_value`, `target_achieved`) |
| "Payments confirmed" sums `payments` by `recorded_by_id` without checking the receipt's status | `eod-service.ts` `payments_confirmed` |
| Target line joins on `customers.owner_id`, not `ASSIGNED_TO_SQL` or `CREDITED_TO_SQL` | `eod-service.ts` `target_amount`, `target_achieved` |
| Order value is `total_amount`, not `orderValueSql` (net of GST) | `eod-service.ts` |
| "Order Calls" in the message is `callsAttempted / queuePending` | `engines/eod.ts` `aggregateEod` |
| Auto-EOD archives the previous calendar day, for every active user | `jobs.ts` auto-eod; `autoGenerateEodReports` |
| `teamEod` runs `eodMetricsForRange` once per person (about twenty subqueries each) | `eod-service.ts` `teamEod` |
