Reminders are rows in `reminders`. The list is `listReminders` in `worklist-services.ts`, which derives the display status on read. Writes come from three directions: the call and collections save paths insert rows inside their own transactions, the Reminders screen calls the services through `lib/actions/crm.ts`, and **every** event that could keep a promise calls `closeRemindersOnEvidence` inside its transaction — a thin wrapper around the pure engine in `lib/engines/reminder-closure.ts`.

<Callout kind="rule">
Pass the **transaction**, never `db`. `closeRemindersOnEvidence` takes `Pick<typeof db, "select" | "update">` so a caller cannot accidentally close reminders outside the write that justified it.
</Callout>

## Access

- **Module:** <ModuleRef k="crm.reminders" />.
- **Scope:** `listReminders` filters by `assigned_user_id in scopedUserIds(scope)`, and hides reminders whose customer is in the lead trash.
- **Writes:** `createReminder` runs `assertCustomerInScope`; `completeReminder` and `dismissReminder` run `requireCapability("reminder.close")`.

## Changing it safely

<Steps>
<Step title="A new kind of evidence goes in the engine">
Add a `ClosureEvent` kind and its `closes` arm and `closureNoteFor` sentence, and a `reminder_closure_source` value. Then call `closeRemindersOnEvidence` from the new write path, inside its transaction.
</Step>
<Step title="Never close what the same write created">
Stamp `call_id` on reminders a call writes, or pass `exclude`.
</Step>
<Step title="Keep hand-closing behind the capability">
Any new "close" or "dismiss" path must call `requireCapability("reminder.close")` and write an audit row.
</Step>
<Step title="Keep the badge and Needs action the same count">
Both are pending and `due_date` on or before today. Change one, change the other.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| `rescheduleReminder` and `holdOtherReasonsUntilReminder` look the reminder up by id with no scope check and no audit row | `worklist-services.ts` |
| The badge counts all pending reminders when `getScope === "team"` (`${teamWide} or …`), the list narrows to the team's ids | `queries.ts` `crmBadgeCounts` vs `listReminders` |
| `hasConflictToday` runs `nextStepForCustomer` once per future reminder on every page load | `worklist-services.ts` `listReminders` |
| Confirmed money closes payment promises outside the confirming transaction (`closeRemindersOnEvidence(db, …)`) | `receipt-service.ts` `closePaymentPromises` |
| `reminders` has both `created_by_user_id` and `created_by_id`, written with the same value | `worklist-services.ts` `createReminder` |
| The reminders page asks `getScope(user)` without naming the app | `app/crm/reminders/page.tsx` |
