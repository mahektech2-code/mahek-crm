Outstanding is `outstandingPage` in `payment-service.ts`: a grouped SQL read that counts and pages customers, then — for the 25 on the page only — `listBills({ openOnly, customerIds })` fed through the pure `groupOutstanding` in `engines/outstanding.ts`. The Accounts app's Outstanding page calls the same function. `listOutstandingByCustomer` is the unpaged version; today only `bill-paging.test.ts` calls it, to prove the paged read and the whole-book read agree.

## Rules the SQL and the engine share

| Rule | In SQL (`outstandingPage`) | In the engine (`groupOutstanding`) |
|---|---|---|
| Only a balance counts | `bills.amount > bills.paid_amount` | `if (r.balance <= 0) continue` |
| Unstated is not debt | `filter (where payment_position = 'stated')` | `unstated` branch adds to `unstatedAmount` |
| Overdue is stated only | `max(overdue) filter (where stated)` | `oldestOverdueDays` updated in the stated branch |
| Order | `outstanding desc, unstated_amount desc, customer_name, customer_id` | same, without the id (it sorts a page already cut) |

The page reorders `groupOutstanding`'s output back into the database's order, because the engine's own sort is wrong for a page cut by name or by age.

## Changing it safely

<Steps>
<Step title="Change the rule in both places, with a test for each">
Any change to what counts goes in `groupOutstanding` and in the `filter (where …)` of `outstandingPage` — and in `recomputeOutstanding`, which is the figure every other screen shows.
</Step>
<Step title="Keep the tie-break">
Every `order by` ends with `customer_id`. Without it a customer appears on two pages and another on none.
</Step>
<Step title="Never cut by financial year">
The year cut belongs to Sales Bills.
</Step>
</Steps>
