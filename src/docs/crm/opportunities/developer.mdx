Opportunities are rows in `call_opportunities`, inserted by `saveInteraction` inside the call's transaction and worked through `opportunity-service.ts`. The screen is a server page reading `listOpportunities()` and a client screen that calls `setOpportunityStatusAction`.

<Callout kind="note">
`lib/engines/opportunity.ts` is **not** this feature. It is the pure arithmetic for a shop's estimated potential against its current sales (`opportunity`, `annualise`) used by the field product. The call-opportunity worklist has no engine.
</Callout>

## Access

- **Module:** <ModuleRef k="crm.opportunities" />.
- **No capability.** Anybody who can see a row may move it; `setOpportunityStatus` re-runs `visibleTo` in its `where`, so a URL-posted id outside scope answers `not_found`.
- **Scope:** `resolveScope()` → `scopedUserIds` → `visibleTo(ids)` (assignee or logger in the ids).

## Changing it safely

<Steps>
<Step title="Keep it off customers.kind">
An opportunity must never promote or demote an account. If a won opportunity should create something, create an order or a reminder through their own services.
</Step>
<Step title="Add a status to the constant and the screen together">
`OPPORTUNITY_STATUSES`, `STATUS_LABEL`, `STATUS_TONE`. The column is text, so the database will not refuse a typo — the constant is the only guard.
</Step>
<Step title="Page in SQL before the list outgrows 500">
Move the counts to a `count(*)`/`sum` query so the cards describe every opportunity, not the loaded page.
</Step>
</Steps>
