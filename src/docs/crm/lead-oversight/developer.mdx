Four modules, almost all reads. **Oversight**, **Lost** and **Funnel & conversion** are services over `customers`, `lead_stage_transitions`, `audit_log` and `app_settings` that write nothing. The **Sales Manager desk** is the same pipeline the Sales Dashboard draws, narrowed by a different scope that travels on the request. Trash, restore and reopen are the only writes. Everything below is cut from the source this deployment was built from.

## Lost and reopen

<Code file="src/lib/services/lead-lost-service.ts" symbol="lostLeadsPage" collapsed />

The rung a lead was lost from is the `from_stage` of its newest `to_stage = 'lost'` transition, joined laterally — never a column on `customers`.

<Code file="src/lib/engines/lead-reopen.ts" symbol="reopenTarget" collapsed />

`reopenSalesManagerLead` asks `lead.verify` and hands the move to `lead-reopen-service.ts`, which validates the code against `leads.reopenReasons` and writes a transition whose note is built by `reopenNote` (it begins "Reopened from Lost"). `reopenDeskLead` is the calling desk's door onto the same rule (it also restarts the three-call count when the target is Suspect).

## Changing it safely

<Steps>
<Step title="Oversight never writes">
A new oversight question is a new read in the service. If it needs a stored answer, the answer belongs on the record it is about.
</Step>
<Step title="Resolve scope inside the service">
Every function here calls `managerScope()` itself. A scope passed in is a scope some caller will forget.
</Step>
<Step title="Never let the Sales Manager scope leak">
`crmSalesManagerScopeFor` applies only when the request is in that workspace. A test that needs it uses `setTestWorkspace`.
</Step>
<Step title="Say legacy gaps in words">
A lost lead with no closing transition shows *Not recorded*; an uncoded move is counted as uncoded. Never infer.
</Step>
</Steps>
