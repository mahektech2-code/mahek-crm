The Calling desk is a **pure engine** (`engines/lead-calling-desk.ts`) that decides where a lead stands from the desk's side, a **read service** that narrows and summarises, and a **write module** whose every action asks the desk's own module grant before it does anything. It writes no stage directly: qualification calls are `calls` rows, and every stage change — Prospect, Lost, reopen — goes through `advanceLeadStage`, the same gated move documented on [All Leads](/docs/crm/leads/developer).

A qualification call is **a row in `calls`**, distinguished only by the `CALL_MARK` key in `outcome_detail`. A separate table would have put half a lead's calls where the record history, EOD counts and the customer timeline do not read.

## Becoming a Prospect

Both buttons share one preparation step, so neither can accept a lead the other would refuse:

- `preparePromotion` — the lead is a working Suspect, the readiness test passes, a sales type is set (or chosen now), a coded reason from `leads.prospectReasons`, a dry run of the Prospect gate, and the verifier is resolved (self-raised verifier → telecaller verifier → sales manager seat → lead manager seat → org-chart candidate → refuse).
- `convertLeadToProspect` — when `leads.callingDeskDirectPromotion` is on, moves the lead with `advanceLeadStage({ to: "prospect" })` and gives the verifier a next action `leads.verificationDueDays` out. When off, it delegates to `requestProspect` unchanged.
- `requestProspect` — leaves the stage alone, writes the `prospect_request_*` columns with state `awaiting`, dates the verification the next working day and notifies the verifier.
- `settleProspectRequest` — after a verification, re-reads the latest verification row itself and, on *verified*, promotes through `advanceLeadStage` under the manager's hat; on *follow up* sets `followup`.

## Reads and scope

<Code file="src/lib/services/lead-calling-desk-service.ts" symbol="callingDesk" />

The desk narrows with `resolveScope` → `scopedToUsers`, **not** `managerScope`: the latter answers "everybody" for anyone without a territory row, which would make one telecaller's desk count the country's leads. Converted leads and archived leads are left out; the query is capped at `DESK_LEAD_CAP` and the list paged at `DESK_PAGE`, while the tiles are counted over the whole capped set.

## Changing it safely

<Steps>
<Step title="Change the rule in the engine">
Which answers are compulsory or needed for a Prospect is a flag on `DESK_FIELDS`. The phase, the ready banner and the button's enabled state all read `prospectProgress`, so one edit moves all three.
</Step>
<Step title="Keep stage writes on advanceLeadStage">
A desk action that set `lead_stage` itself would skip the gate, the transition row and the timeline.
</Step>
<Step title="Every new write asks deskRefusal">
Put it immediately after `requireCapability("lead.work")`.
</Step>
<Step title="Do not store derived state">
"Ready" and "which call" are derived on every read. Only the request is stored, because asking is not being.
</Step>
</Steps>
