The Dashboard is one server page, `src/app/crm/dashboard/page.tsx`, that paints its header immediately and streams the figures behind a `Suspense` boundary. The figures come from three places: `rangeActivity`/`teamRange` in `lib/queries.ts` (both wrapping `eodMetricsForRange` in `eod-service.ts`), today's work from the queue, payment and worklist services, and two private queries in the page file for the manager's red flags.

| Layer | File | What lives there |

<Callout kind="rule">
The header and the **Start calling** link render before any figure is awaited. An `await` in the page body blocks the page; the same `await` in a child component behind `Suspense` streams. Keep slow reads inside `DashboardFigures`.
</Callout>

Notes for whoever edits `eodMetricsForRange`:

- Every timestamp window carries the business zone through `windowFor(range)` — half-open `[start, end)` instants. Never `::date` a timestamp.
- `payments.paid_at` is a **date** and is compared against the range's dates, inclusive.
- The monthly target uses a month window (`mw`) for the month `range.to` falls in, not `extract(month …)`, which cannot use the index and is evaluated in the session zone.
- Connect rate is computed from summed counts in `rangeActivity`, never averaged.

## Changing it safely

<Steps>
<Step title="Add a count to eodMetricsForRange, not to the page">
A figure the EOD report could also want belongs in the shared function, with its window from `windowFor`. A second spelling in the page is how the dashboard and the EOD report disagree.
</Step>
<Step title="Decide whether it follows the period">
Activity follows the period. Work waiting now does not. Put the new figure on the right side of `PeriodBar`.
</Step>
<Step title="Use the order-status list, not literals">
Read `orderCountsSql` / `PURCHASE_STATUSES` from `lib/order-status.ts` for "did we sell anything".
</Step>
<Step title="Make thresholds settings">
Add flag ages to `registry.ts` under `dashboard.*` with a `Config` type entry.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| Approved orders are filtered by a literal `('captured','confirmed','dispatched')`, missing `in_transit` and `delivered` from `PURCHASE_STATUSES` | `eod-service.ts` `eodMetricsForRange` (`orders_count`, `orders_value`, `target_achieved`) |
| `payments_confirmed` sums `payments` lines by `recorded_by_id` with no join to `payment_receipts.status` — reported and rejected money is counted as collected | `eod-service.ts` `eodMetricsForRange` |
| `target_amount` / `target_achieved` join on `cu.owner_id` rather than `ASSIGNED_TO_SQL` or the sales-attribution rule | `eod-service.ts` |
| `overSixtyDays` is unscoped, uses `current_date` (session zone) and does not exclude `unstated` bills | `dashboard/page.tsx` |
| `overdue_growth` and `complaints_flagged` filter by `cu.owner_id`; growth includes unstated bills and is a fixed 7-day window | `dashboard/page.tsx` `dashboardCounts` |
| Team-table red thresholds (`overdueReminders > 3`, `callsMissed > 5`) and "Not reachable - retry after 4 pm" are literals | `dashboard/page.tsx` `TeamView`, `DashboardFigures` |
