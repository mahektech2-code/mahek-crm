The CRM is a Next.js App Router subtree at `src/app/crm`. One layout gates the app and builds the shell; one layout per module gates each screen; every page is a server component that calls **reads** from `lib/queries.ts` or a `lib/services/*` file and hands plain data to a client screen, and every button calls a **server action** in `lib/actions/*` that delegates to the same services. Pure rules live in `lib/engines/` and never touch the database.

`scopedToUsers` answers "may this reader see the row" and reads **both** working seats (sales and back office, plus the lead manager and relationship seats). `ASSIGNED_TO_SQL` answers "whose book is it" and reads exactly one. Do not substitute one for the other: the first is for visibility, the second for credit and for the "Assigned to" column.

## Writes

Every action in `lib/actions/crm.ts` has the same shape: a `try`, a call into the service, `refreshAll()` to revalidate the CRM's paths, and `fromThrown(e)` on failure so the client always receives a `Result` rather than an exception. Permission is checked **in the service** with `requireCapability` or `assertCustomerInScope` — never by hiding a button.

## Adding a CRM screen safely

<Steps>
<Step title="Register the module">
Add it to `APP_MODULES` in `lib/modules.ts`. The key is stored in `app_module_access` — choose it once, never rename it.
</Step>
<Step title="Add the nav item">
`NAV` in `components/shell/nav.ts`. A nav item without a module is filtered out, which is the safe failure.
</Step>
<Step title="Guard the folder">
Give the route a `layout.tsx` that calls `requireModule`. The sidebar hiding a link is a courtesy, not a permission.
</Step>
<Step title="Read through a service, scoped">
Use `resolveScope()` and `scopedToUsers` or `ASSIGNED_TO_SQL`. Never write a second spelling of whose book an account is in.
</Step>
<Step title="Write through an action that checks">
`requireCapability` or `assertCustomerInScope` in the service. Return a `Result` and call `refreshAll()`.
</Step>
<Step title="Claim it in the docs registry">
`src/docs/registry.ts` — the coverage test fails until a page claims the new module.
</Step>
</Steps>

| Gap | Where |
|---|---|
| The Reminders badge is company-wide for any team-scope reader; the list is narrowed to the team | `lib/queries.ts` `crmBadgeCounts` (`${teamWide} or …`) vs `worklist-services.ts` `listReminders` |
| Complaints badge and dashboard complaint flags filter by `owner_id`, not `ASSIGNED_TO_SQL` | `lib/queries.ts` `crmBadgeCounts`; `app/crm/dashboard/page.tsx` `dashboardCounts` |
