My Performance is a server page over **one service read**, `readingsForPeriod`, narrowed to the signed-in user. The arithmetic is a pure engine (`engines/performance.ts`); the actuals and their attribution are SQL in `performance-service.ts` through one crediting rule (`sales-attribution.ts`); the stored score cache (`sales_performance`) is rebuilt hourly and nightly for the handset and the Sales Dashboard. Everything below is cut from the source this deployment was built from.

## Actuals

<Code file="src/lib/services/performance-service.ts" symbol="actualsForWindow" collapsed />

- Day windows in SQL carry `+05:30`; a bare bound reads in the session zone.
- Order value is `orderValueSql` (net of GST, after discount) over `orderCountsSql` rows.
- Litres = cans × `products.millilitres_per_can`; an unmatched product name adds revenue, no litres, and `unmatched_revenue_paise`.
- Collection reconstructs each bill's balance **as of the window start** from confirmed allocations received before it (`bills.paid_amount` is current, not historical), excludes `unstated` bills, and skips receipts keyed `creditnote:%`.
- Activity reads tasks by `assigned_to_user_id`, due inside the window.

## Changing it safely

<Steps>
<Step title="A seventh component touches four places">
`COMPONENT_KEYS`, a weight key in the registry (and the total-100 consistency check), the actual in `actualsForWindow`, and a column in `sales_performance`.
</Step>
<Step title="Credit through one rule">
Any new actual is grouped by `creditedToSql`. Never by `ASSIGNED_TO_SQL` (it ends at the importer) or `scopedToUsers` (two people).
</Step>
<Step title="Null is not zero">
Keep `achievementBp` returning null for no target, and keep the dropped component named.
</Step>
<Step title="Never reinterpret a stored target">
New target shapes get new columns; old rows keep scoring the way they were written.
</Step>
</Steps>
