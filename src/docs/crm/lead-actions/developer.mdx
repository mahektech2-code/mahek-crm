Two modules share this page. **Next actions & nurture** (<ModuleRef k="crm.lead-actions" />) is reads over four `customers` columns plus a pure engine that turns events into `mbos_tasks` rows keyed for idempotency. **Handovers** (<ModuleRef k="crm.lead-handovers" />) writes one seat — `relationship_owner_id` — with its history and timeline in one transaction. Everything below is cut from the source this deployment was built from.

## Changing it safely

<Steps>
<Step title="A new nurture row is a row in NURTURE_SEQUENCE">
Add a trigger to `NurtureTrigger` if needed, then make sure something raises it — an action calling `raiseNurtureTasks` and an event query in `runNurturePass`. A row nothing raises is a promise nothing keeps.
</Step>
<Step title="Never put a moving value in the key">
Not the due date, not the title. Changing either would re-raise every outstanding task.
</Step>
<Step title="Do not let the relationship seat leak into ASSIGNED_TO_SQL">
That expression credits revenue. Reading the handover seat there would move money between people as a side effect of naming a relationship manager.
</Step>
<Step title="Handover refusals are pure">
Add a refusal to `handoverRefusal` and `HANDOVER_REFUSALS` so the screen's disabled button and the action say the same thing.
</Step>
</Steps>
