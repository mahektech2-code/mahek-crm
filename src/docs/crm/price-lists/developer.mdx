Price lists are one feature mounted in four apps — the CRM, the Sales Dashboard, Accounts and the Founder Dashboard — through shared components in `src/components/pricing/` and one service, `price-list-service.ts`. The CRM mount is **read-only for everybody**: `priceListDoorCanManage(user, "crm")` answers no before it asks any capability. Which list applies to a shop is the pure `resolvePriceList`; the money arithmetic is `price-math.ts`; every write is in `lib/actions/price-lists.ts` behind `requirePriceDesk()` — the capability **and** the desk module it was worn at.

## Changing it safely

<Steps>
<Step title="Resolution rules go in the engine">
`resolvePriceList` is compiled by the handset too. A rule in a service would make the salesman and the office disagree about one shop.
</Step>
<Step title="Never edit a published list's prices">
Add a version. An order taken in August must stay explainable in December.
</Step>
<Step title="Every write behind requirePriceDesk">
Not just `pricelist.manage` — the desk module it was worn at as well.
</Step>
<Step title="Keep the CRM door closed">
`priceListDoorCanManage` returns `false` for `"crm"` before asking anything. Do not let a second hat draw an editor on a telecaller's screen.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| Resolution checks status and start/end dates but not `validity_days`; an expired list still prices shops | `engines/price-resolution.ts` `resolvePriceList` |
| Publishing a new version supersedes the old one immediately, even when the new one starts later | `actions/price-lists.ts` `publishPriceList` |
| A customer-named list wins whole resolution; products not on it get no rate | `engines/price-resolution.ts` |
| Above-ceiling discounts are refused; there is no manager-authorise flow despite the message | `engines/price-math.ts` `discountAuthority` |
| Variance resolves past months against today's lists and is not scoped to the reader's book | `price-list-service.ts` `varianceReport` |
| Slabbed rates are not used on the order form or in variance | `price-list-service.ts` `ratesForCustomer`, `varianceReport` |
