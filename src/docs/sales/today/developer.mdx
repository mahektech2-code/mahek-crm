Today is a server page that makes two reads — `teamDay(day)` and `consoleCounts(day, tomorrow)` — both in `src/lib/services/sales-service.ts` and both narrowed by `managerScope()`. The client component renders, filters and sorts; it never fetches. `consoleCounts` is the same function the layout calls for the sidebar badges, so the card and the badge for one kind cannot disagree.

## Map of the code

| Layer | File | What lives there |
|---|---|---|
| Module guard | `src/app/sales/page.tsx` | `requireModule(user.id, "sales.today")` — the app root has no folder layout of its own |
| Page (server) | `src/app/sales/page.tsx` | Parses `?day=`, builds the greeting and the six `waiting` cards |
| Screen (client) | `src/app/sales/today-screen.tsx` | Day switcher, four `Stat` cards, waiting cards, `TeamTable` with filters, search and sort |
| Reads | `src/lib/services/sales-service.ts` | `teamDay`, `consoleCounts` |
| Day link | `today-screen.tsx` `dayHref` | Opens the salesman's day (`/sales/live/[id]`) in a new tab |

## `teamDay`

One row per person holding the `field` app, left-joined to that day's `mbos_attendance_days` row, with correlated subqueries for visits, unverified visits, orders and value (`source = 'mbos'`), collected (`source = 'mbos'`, not rejected) and planned/walked stops. Every timestamp is cast to a date with the zone named — never a bare `::date`.

<Callout kind="rule">
Orders are counted by `created_by_id` — the salesman who took them — not by whose book the customer is in. Today answers "what did each person do", not "whose revenue is it". Attribution for revenue is `lib/sales-attribution.ts`; see [Performance](/docs/sales/performance/developer).

## `consoleCounts`

One statement of scalar subqueries, each narrowed by `onlyMine(scope, …)` on the column that names the person. It also produces the header's `teamLine`, `scopeDetail` and `liveLine`.

## Access

- **Module:** <ModuleRef k="sales.today" />, checked in `page.tsx`.
- **Scope:** both reads call `managerScope()`; it is cached per request, so the layout's call and the page's call cost one resolution.
- **No writes.**

## Changing Today safely

<Steps>
<Step title="Add a waiting card in two places">
Count it in `consoleCounts` (so the sidebar badge and the card read one number) and add the card to the `waiting` array in `page.tsx` with the screen that decides it.
</Step>
<Step title="Narrow every new count">
Use `onlyMine(scope, column)` on the column that names the salesman. A count that skips it shows a regional manager the whole company.
</Step>
<Step title="Name the zone">
Any timestamp turned into a day uses the `IST_DAY` fragment. Two grep tests fail the build on a bare cast.
</Step>
</Steps>
