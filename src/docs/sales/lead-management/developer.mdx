The Sales Dashboard's lead routes are thin wrappers: each `page.tsx` under `src/app/sales/leads/**` and `src/app/sales/samples/**` renders a shared `Body` from `src/components/leads/pages/*` with `workspace="sales"`. The workspace decides the base path and the module key; `managerScope` decides the rows. The full engine, service and action documentation is on the CRM lead pages — start at [Leads → Developer](/docs/crm/leads/developer).

## Map of the code

| Layer | File | What lives there |
|---|---|---|
| Section list (pure) | `src/lib/lead-workspace.ts` | `LeadWorkspace`, `LEAD_SECTIONS`, `leadHref`, `leadModuleKey`, `sectionForPath`, `NAV_RETIRED_SLUGS`, `OTHER_DESK_SLUGS` |
| Modules | `src/lib/modules.ts` | `sales.leads` … `sales.lead-oversight`, and `sales.lead-pipeline` (`offByDefault`, `explicitOnly`) |
| Routes | `src/app/sales/leads/**`, `src/app/sales/samples/**` | `<Body workspace="sales" />`; each module folder carries its own `requireModule` |
| Folder layout | `src/app/sales/leads/layout.tsx` | Deliberately **no** guard — nine modules live under this path |
| Sales Manager workspace | `src/app/sales-lead-pipeline/**` | Own layout: `sales` grant, then `requireModule("sales.lead-pipeline")`; dashboard, pipeline, list, record |
| Shared screens | `src/components/leads/pages/*` | One body per screen, both apps |
| Sidebar | `src/app/sales/nav.ts`, `sidebar-nav.tsx` | Four visible rows; seven `legacy` rows drawn only without All Leads |
| Request app | `src/proxy.ts` | `APP_ROUTES` maps `/sales` and `/sales-lead-pipeline` to `sales`; `WORKSPACE_HEADER` marks the CRM's Sales Manager desk |
| Scope | `src/lib/services/sales-service.ts` | `managerScope`, `leadsVisible`, `scopeNarrowing` |

## Changing it safely

<Steps>
<Step title="Add a screen once">
Write the body in `src/components/leads/pages`, add a tab to `LEAD_SECTIONS`, and add a two-line route in each app. Never spell `/sales` or `/crm` inside a shared screen — use `leadHref`.
</Step>
<Step title="A new section is a module in both apps">
Add `sales.<slug>` and `crm.<slug>` in `modules.ts`; `lead-workspace.test.ts` fails until both exist.
</Step>
<Step title="Put the guard in the module folder">
Not in `src/app/sales/leads/layout.tsx`, which would refuse a grant it knows nothing about.
</Step>
<Step title="Route a new top-level path through the proxy">
Any lead route outside `/sales` needs an `APP_ROUTES` entry, or its scope resolves against the wrong app.
</Step>
</Steps>
