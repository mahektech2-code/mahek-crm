Two server pages, two services. `/sales/performance` calls `readingsForPeriod(month, today)` and `unattributedForPeriod(month)` in `src/lib/services/performance-service.ts` — the same functions the CRM's own performance screen and the handset's cache rebuild use — and the person drawer fetches `/api/sales/performance` for one person and range. `/sales/roi` calls `salesmanRoi`, `customerCosts` and `expenseBreakdown` in `src/lib/services/expense-roi-service.ts`, which feed the pure `src/lib/engines/sales-roi.ts`. The scoring engine and its tables are documented on [Performance in the CRM](/docs/crm/performance/developer); this page covers the team view.

## Changing it safely

<Steps>
<Step title="Change the score in the engine">
Never compute a component in the page. The CRM screen, the handset cache and this screen all read `readingsForPeriod`.
</Step>
<Step title="Credit through creditedToSql">
Any new revenue figure on either screen uses the one attribution rule. A second rule is how two screens credit one invoice to two people.
</Step>
<Step title="Narrow by the patch">
Pass `userIds` from `managerScope` if you touch the Performance page — see the gap below.
</Step>
</Steps>
