Documents are `mbos_documents` rows with exactly one `attachments` row behind them (parent type `mbos_document`); courses are `mbos_courses`, optionally with a file (parent type `mbos_course`), and `mbos_course_progress` per salesman. The office writes through `src/lib/actions/sales.ts`; handsets receive them on the pull from `src/lib/services/mbos-service.ts` and learn what stopped from `mbos_deletions`.

## Access

<ModuleRef k="sales.documents" /> <ModuleRef k="sales.knowledge" />

Writes use `requireSalesAccess(SALES_MANAGER(module))`. A course is filed under its own attachment parent, not `mbos_document`, because `canRead` decides who may open a file from the parent kind — a course deck read under the document rules would meet role lists and a customer scope a course does not have.

## Changing it safely

<Steps>
<Step title="Every way a phone loses sight of a row needs a tombstone">
Withdraw, untag, a narrowed audience — each must write to `mbos_deletions`, scoped to the people affected.
</Step>
<Step title="Every way it regains sight must lift the tombstone">
Upserts apply before tombstones on the handset; a standing tombstone deletes a row the same pull delivered.
</Step>
<Step title="Never publish a row without its file">
Bind first, and roll the row back if binding fails.
</Step>
</Steps>
