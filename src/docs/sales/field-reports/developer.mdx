Field reports is a read-only page over five sources, each defined once as a FROM-clause in `src/lib/services/field-reports-service.ts` and read twice — by its own list and by the single query that counts all five tabs. Activity history is `activityHistory()` in `src/lib/services/sales-service.ts`, which merges MBOS visits with staged rows from the retired EMP 2.0 app. Those rows are pulled by `src/lib/services/field-activity-sync-service.ts`, matched by the pure `decideCustomerMatch` in `src/lib/field-activity-match.ts`, decided by people through `src/lib/actions/field-activity.ts`, and projected onto `timeline_events` by `src/lib/services/field-activity-projection-service.ts`.

## The EMP 2.0 pipeline

<Flow caption="From the old app's sheet to a customer's timeline" chart={`
sequenceDiagram
  autonumber
  participant G as Activity tab (Google Sheet)
  participant Y as field-activity-sync-service.ts
  participant M as field-activity-match.ts
  participant DB as Postgres
  participant P as projection service
  G->>Y: append pass (watermark) or reconcile pass (full hash compare)
  Y->>Y: parse rows, drop rows on or after fieldActivity.cutoverDate
  Y->>DB: upsert sheet_field_activity_rows by activity_id and row_hash
  Y->>DB: exact salesman match on the folded name
  Y->>M: decideCustomerMatch(exact, near, decision)

  P->>DB: every matched, unprojected row becomes a timeline_events visit`} />

The sheet id is a constant in the sync service, overridable by an environment variable for a staging copy; the Google credential stays in the environment. API modes: `?mode=field-activity` (append), `field-activity-reconcile`, `field-activity-project`, plus rematch and reparse.

## Access

- **Modules:** <ModuleRef k="sales.field-reports" />, <ModuleRef k="sales.activity-history" />.
- **Deciding a shop:** manager level and `sales.activity-history` (`requireDecider` → `salesGateRefusal`).
- **Scope:** field report tabs narrow by `managerScope` on whoever filed the item; Activity history narrows matched rows to the manager's salesmen and shows unmatched rows to everybody.

## Changing it safely

<Steps>
<Step title="Change the match rule only in decideCustomerMatch">
Then run the re-match: a hash-driven sync never re-asks an unchanged row.
</Step>
<Step title="Never auto-link a close name">
A wrong link is a visit on somebody else's timeline, read as fact.
</Step>
<Step title="Add a field report tab as one FROM-clause">
Read it in both its list and `fieldReportCounts`, narrowed with `onlyMine`.
</Step>
</Steps>
