The Live map is a server page that reads the team's last positions (and, on the day view, every track and activity mark), derives the banners once, and hands everything to a client `LivePanel` that keeps itself current over a server-sent-events stream (`/api/sales/live/stream`, falling back to `/api/sales/live/delta`). The map is MapLibre over Ola Maps tiles in `street-map.tsx`. Road snapping is a separate, per-person request to `/api/sales/live/snap-trail`. Positions arrive from handsets at `POST /api/mbos/positions`.

`street-map.tsx` draws one of four frames: no key / all keys spent, failed (the **style** never loaded within the timeout — a single bad layer in Ola's style does not fail it), nothing to place (drawn over a mounted host so the map can build when the first fix arrives), or the map. ## Access

- **Module:** <ModuleRef k="sales.live" /> on the page, and `canOpenModule(user.id, "sales.live")` in each of `delta`, `stream` and `snap-trail`.
- **Scope:** `managerScope()` in every read; `liveDeltaFor` takes the scope resolved in the request, never inside a stream tick.

## Changing it safely

<Steps>
<Step title="Put rules in the engines">
Anything about what a trail means belongs in `lib/engines/trail-*.ts` and runs identically in the page, the stream and the browser.
</Step>
<Step title="A new handset fact goes in three places">
The handset's device report, a nullable column on `mbos_devices` (omitted, never nulled, by older builds), and a sentence in `handsetNotes` with a test.
</Step>
<Step title="Keep snapping optional">
Every road-snap failure path must return null so the raw line stays. Never write snapped geometry back into `mbos_positions`.
</Step>
<Step title="Never widen managerScope for this screen">
It guards selfies and odometer photos as well.
</Step>
</Steps>
