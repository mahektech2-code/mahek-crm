The Quotation manager is its own route, `app/erp/quotation-manager`, not a generic list screen: it is a table you type into, like a spreadsheet, in which rows, columns and cells are all edited in place, with a side panel and a footer reading the selection.

## One write

<Code file="src/lib/erp/quotes.ts" symbol="applyQuoteOps" />

A cell moving to `po` with no PO number takes the next number of the ERP's `po` series — or, where the dialog chose **Add to PO-…**, that open PO's number, checked again by `joinablePoNumber` — and `orderFromQuote` writes the PO line in the same transaction; a refusal there rolls the whole save back. A cell leaving `po` for anything but `pickup` calls `withdrawQuotePo`, which is refused once goods are received.

<Code file="src/lib/erp/engines/quotes.ts" symbol="quoteStatusRefusal" />

Ids for new rows and columns are minted on the screen (`newQuoteId`) so a paste can create rows and fill them in one list; the server accepts an id only in that shape. A cell write checks the column's kind on the server, whatever the screen did. One audit row (`erp.quotes.edit`) is written per save, with the count of each kind of change.

## Undo

<Code file="src/lib/erp/engines/quote-sheet.ts" symbol="invertSheetOps" />

The inverse is read off the state before the change and every inverse is an op the server accepts — a created row is undone by deleting it, a created column by archiving it — so Undo is just another save. Redo is the inverse of an undo, kept on its own stack and cleared by any new change.
