Alerts are three files: the pure rules in `engines/alerts.ts`, the run that gathers facts and raises or resolves in `lib/erp/alerts.ts`, and the list module in `screens/alerts.ts`. The morning summary is `digest.ts`. Every AI helper goes through `lib/erp/ai.ts` — one gate (`featureState`), two readers (`readImages`, `readText`) and one log (`erp_ai_suggestions`) — and then a helper file per feature that turns a reading into a review form and applies it through the owning screen's rules.

## Access

- **Module:** <ModuleRef k="erp.alerts" />.
- `visibleAlerts(ctx.screens, ctx.powers)` filters every list, acknowledgement and resolution; `ack` and `resolve` refuse an alert not in it.
- **Run checks now:** `ctx.administrator || ctx.level === "manager"`.
- Helpers inherit the screen they sit on; bill reading also needs `viewPurchaseMoney`. Ask the ERP needs only an ERP level, then each tool checks `ctx.screens`.

## Changing it safely

<Steps>
<Step title="A new alert is a pure rule plus a fact query">
Write the rule in `engines/alerts.ts` with a test, give it a label in `ALERT_LABEL`, add its fact query to `currentCandidates`, and its thresholds to `Thresholds` and the registry. Set `power` if the sentence shows money or cost.
</Step>
<Step title="Pick a stable subject">
The subject is what makes "once" hold. A subject that changes between runs raises a new alert every hour.
</Step>
<Step title="A new helper goes through featureState and logSuggestion">
Give it a switch and a monthly cap in the registry, add it to `AiFeature`, `SWITCH` and `CAP`, log the reading before anybody decides, and save only through the owning screen's own form with `decideSuggestion` on the way out.
</Step>
<Step title="Ask the ERP gets a tool, never SQL">
A new question is a tool in `askTools` that calls `fromScreen` on an existing screen module, so it answers with exactly the person's view.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| A hand-resolved alert whose condition still holds is raised again as a new alert on the next run | `alerts.ts` `runErpAlerts`; `screens/alerts.ts` `resolve` |
| `erp_alerts_open_key` exists only in the migration, not in `schema.ts` | `drizzle/0180_erp_alerts_and_ai.sql`; `db/schema.ts` `erpAlerts` |
| The digest's writing model is `voice.languageModel`, not `erp.ai.textModel` | `digest.ts` `writeErpDigest` |
| `readyUnbilled` uses the line's `updated_at` as "Ready since" | `alerts.ts` `currentCandidates` |
| `belowLevel` for raw materials is fed by rows below the maximum | `screens/movement.ts` `rmReorderRows` |
