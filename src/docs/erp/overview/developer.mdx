The ERP is **data-driven**. One registry (`lib/erp/registry.ts`) lists every screen and its tabs; one context (`erpContext`) says who the person is inside the ERP; one dynamic route (`app/erp/[slug]/page.tsx`) draws any list screen from a **screen module** in `lib/erp/screens/`; and every write goes through four server actions in `lib/actions/erp.ts`. The handful of bespoke screens — dispatch, trace, the PO print, labels, settings — live in their own route folders. This tab is the map; each area's page has its own developer tab.

<Callout kind="rule">
The engines in `lib/erp/engines/` perform **no I/O**, like every engine in MahekOne. The form previews a figure with the same function the server stores it with (`calc` names on derived fields map to `lib/erp/calcs/`), so the preview and the save cannot disagree.
</Callout>

## The four doors for writes

<Code file="src/lib/actions/erp.ts" symbol="erpRunAction" />

`erpRunBulk`, `erpSubmitForm` and `erpRunTool` have the same shape. ## Access and modules

- **Modules:** one per built screen, e.g. <ModuleRef k="erp.dashboard" />, <ModuleRef k="erp.stock" />. Tabs are not modules.
- **No capabilities.** The ERP's row in `capability-matrix.ts` is empty on purpose; decisions are ERP **powers** (`lib/erp/powers.ts`). See [Access and designations](/docs/erp/access-and-designations/developer).

## Adding a screen safely

<Steps>
<Step title="Declare it in the registry">
Add it to its group in `ERP_GROUPS` with `built: false` while it is being written — an unbuilt screen is not a module, so nothing can be granted onto a page that does not exist. Its key becomes `erp.<key>` and is a grant: never rename it.
</Step>
<Step title="Write its module">
A `ScreenModule` in `lib/erp/screens/`, registered in `screens/index.ts`. Mark money columns with `pw`, run every list through `visibleCols`/`withoutHidden`, and give every refused action a `why`.
</Step>
<Step title="Check the power inside every handler">
The four doors check the screen; the handler checks the power. A hidden button is not a permission.
</Step>
<Step title="Consume stock only inside a transaction that locks the lot">
`lockLot`, then read stock with the transaction (`rmLots(tx)` etc.), then refuse with `refuse(...)` inside `inTx`.
</Step>
<Step title="Flip built, add a dashboard tile and a badge from the same function">
A tile and a badge that count with different queries will disagree.
</Step>
<Step title="Claim the new module in the docs registry">
`src/docs/coverage.test.ts` fails until a documentation page claims it.
</Step>
</Steps>
