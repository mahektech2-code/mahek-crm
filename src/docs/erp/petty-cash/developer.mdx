Petty cash is one ERP screen (`expenses`) with thirteen tabs, each its own server module across three files: `screens/petty-expenses.ts` (Expenses, Payments, Vendor outstanding), `screens/petty-funds.ts` (Overview, Funds given / transfers, Customer cash, Daily closing, Fund ledger, Settings) and `screens/petty-books.ts` (Bank reconciliation, Budgets, Reports, Tally sync). The screens never write to a table directly: every write is a function in `lib/erp/petty/`, and every balance movement goes through **one** function, `post` in `petty/core.ts`. The rules are pure, in `engines/petty-cash.ts`. This page covers the everyday half; the closing half is on [its own developer page](/docs/erp/petty-cash-closing/developer).

## Access

- **Module:** <ModuleRef k="erp.expenses" />; all thirteen tabs come with it.
- **ERP powers:** `pettyAccounts`, `pettyApprove`, `pettyOwner` (read by `pettyRoles`); an ERP administrator holds all three.
- Every write: `requireErpWrite(<tab key>)`, then the function's own role and maker-checker checks. The audit row is written inside the same transaction as the money (`petty/core.ts` `audit`).

## Changing it safely

<Steps>
<Step title="Move money only through post">
A new kind of movement is a new `txnType` and `postingKey` shape passed to `post`. Never insert into `erp_fund_ledger` directly — the trigger will stop an update, but nothing stops a second insert path from skipping the closing reopen.
</Step>
<Step title="Lock before you read a balance you will refuse against">
`lock(tx, "expense:…", "fund:…")` then `balanceIn(tx, …)`. Reading the balance outside the transaction lets two payments both pass.
</Step>
<Step title="Keep the rule in the engine">
The screens, the exception queue and the tests all call `engines/petty-cash.ts`; a limit or a route typed into a screen is a second answer.
</Step>
<Step title="Give every form a request key">
`requestKey()` in `petty-shared.ts`, stored on the row with a unique index, is what makes a retry harmless.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| An urgent payment (before approval) can be recorded by anybody holding the screen | `petty/expenses.ts` `payIn` |
| `cashBalances` (credits less expenses per employee) is tested but read by nothing | `engines/cash.ts` |
| A bank fund may be sent more than it holds on a transfer (only cash funds are checked) | `petty/funds.ts` `initiateTransfer`, `confirmTransfer` |
| An expense names its spender as free text, so maker-checker matches names case-insensitively — two staff with one name block each other | `engines/petty-cash.ts` `decisionRefusal`; `screens/petty-expenses.ts` `expenseRow` |
