Purchase orders are the `purchaseOrders` screen module in `lib/erp/screens/purchase-flow.ts`, with the arithmetic and status rules in `lib/erp/engines/purchase-flow.ts`. The receiving side lives in `screens/purchase.ts` and calls back into `refreshPurchaseOrder`. The printable PO is its own route, `app/erp/po/[id]/page.tsx`.

## Map of the code

| Layer | File | What lives there |
|---|---|---|
| Engine (pure) | `src/lib/erp/engines/purchase-flow.ts` | `LIVE_PO`, `RECEIVABLE_PO`, `poLabel`, `poLineFigures`, `poTotals`, `poStatusAfterReceipt`, `receivableQuantity`, `poMessage` |
| Reading | `src/lib/erp/screens/purchase-flow.ts` | `purchaseOrderViews`, `receivedByLine`, `poOption` |
| Form | same | `poFormData`, `purchaseOrderForm` (header + lines, filled from the selected quotation / vendor) |
| Writes | same | `savePurchaseOrder`; actions `approve`, `sendBack`, `send`, `close`, `cancel`; form loader `receive` → `inwardFormForPo` |
| Approval rule | same | `approvalRefusal` — duties per line, else the power |
| After a receipt | same | `refreshPurchaseOrder(tx, poId)` |
| Print | `src/app/erp/po/[id]/page.tsx` | Approved POs only; needs `viewPurchaseMoney` |
| Badge | same | `purchaseFlowCounts` |

## Permissions

- **Module:** <ModuleRef k="erp.purchaseOrders" />. Receive goods also needs <ModuleRef k="erp.register" /> (the Purchases screen, whose Goods receipt tab is `inward`).
- **Powers:** `viewPurchaseMoney` (raise, edit, print), `approvePurchaseOrder` (approve, send back — unless the material names its approvers).
- **Duties:** `raisePo` (raise / edit, every line), `approve` (every line).

## Changing it safely

<Steps>
<Step title="Never store what was received">
Read it with `receivedByLine`. A stored figure needs a recompute path and a way to be wrong.
</Step>
<Step title="Every receipt path calls refreshPurchaseOrder in its transaction">
A new way of receiving goods that forgets leaves the PO at Sent with the goods in stock.
</Step>
<Step title="Keep the self-approval check inside the locked transaction">
`approve` re-reads the PO `for update` before checking status and raiser, so two approvers cannot both approve.
</Step>
</Steps>
