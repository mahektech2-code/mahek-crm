The Orders screen is seven tabs, each its own server module: five built in `screens/sales.ts` (`orderList` for four scopes, plus `batchCodes` and `orderDetails`) and the inbox in `screens/inbox.ts`. Every list reads one function, `orderLines()`, so a line cannot be Ready on one tab and something else on another. The arithmetic is pure in `engines/sales.ts`; every write ends with `syncBookOrders`, which projects the change into MahekOne's order book (covered on [the order book page](/docs/erp/order-book/developer)).

## Access

- **Module:** <ModuleRef k="erp.orders" />. All seven tabs come with it; none is grantable alone.
- **Powers** read here: `viewSalesRate`, `viewSalesAmounts`, `viewCost` (columns and fields, via `visibleCols` / `withoutHidden` — values are stripped server-side), `approveParty` (Approved By Admin, and only while `erpOrdersLive()` is false). `notVerify` checks `ctx.administrator`.
- Every write is `requireErpWrite(<tab key>)`; a preview refuses all of them.

## Changing it safely

<Steps>
<Step title="Read orderLines, never re-query a line">
Every tab, the alerts and Ask the ERP read `orderLines()` / `detailRows()`. A screen with its own SQL for "is this line Ready" will disagree with the Dispatch desk.
</Step>
<Step title="Keep the arithmetic in engines/sales.ts">
And keep `calcs/sales.ts` as a preview only — the server recomputes everything on save.
</Step>
<Step title="Call syncBookOrders after every write that changes a line">
The CRM, targets and outstanding read the projection, not `erp_orders`. A write that forgets it leaves the order book stale until the next change to that order.
</Step>
<Step title="Withhold money server-side">
A new money column takes a `pw:` on its `Col` so `visibleCols` drops it and `withoutHidden` strips its value.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| Pending hides every line of an order once any line of it is billed (`detailedOrders` keys on order number) | `screens/sales.ts` `inScope` |
| `allocateForm` / `saveAllocation` have no row action on any Orders tab; reachable only from the Dispatch desk | `screens/sales.ts` `orderList`; `app/erp/dispatch/desk.tsx` |
| A line set **Not Verify** cannot be verified again (verify accepts only null or Pending) | `screens/sales.ts` `verify` |
| `saveEdit`'s reset of `entry_status` when a Done line's quantity moves is unreachable: a billed line's quantity is refused first | `screens/sales.ts` `saveEdit` |
| The `readyUnbilled` alert dates Ready from `updated_at` | `lib/erp/alerts.ts` `currentCandidates` |
| `issuedCreditNotes` keys on the CRM bill number and goods text, and `creditOf` on the line's Tally bill no. and SKU name; a credit note whose goods text differs from the SKU name never reaches the margin | `screens/complaints.ts` `issuedCreditNotes`; `screens/sales.ts` `creditOf` |
