**One plan per day.** The date is unique, so pressing Create daily plan for a day that has one opens it. Adding a line always writes into the same plan. A plan can only be made for today or a later day.

**The ticked rows are the plan, written at print.** Pressing Print plan writes each ticked row as a plan line (updating the line already there, or adding one) and marks every other line deleted, in one transaction, then records the print. A line is never removed, because a line the floor already had must be named on the next print. Typing a line with Add a line saves it at once.

**Every print is remembered.** A print stores the lines exactly as they were. The colours on screen and the underline on paper both answer one question: was this line on the last print, exactly as it is now? Printing again with nothing changed opens the last print rather than making a second copy.

**Stock is read, never moved.** Available now is the semi-finished stock for an SFG base, the finished-goods (loose can) stock for a product and can size, and the packed stock for a boxed SKU, all at the plan's godown. The plan's godown is the creator's working location when the plan was made. Recording the actual work still happens on SFG batches, FG filling and Packing batches.

**Who can use it.** The screen is the `erp.underProcess` module on the Access screen. The Production Head designation carries it.

## Where the code and the intent disagree today

- **Product code** is the product's legacy Product ID where one exists. SFG bases carry no code, and some products have none, so those show a dash.
- **Unit** is offered from a short list per category (Litre or Kg, Cans, Boxes or Cans). A unit other than those is refused.


## The orders come in by themselves

The table is built every time the plan opens from the lines Orders → Production lists as Under Process (status Under Process, entry not Done, empty drums left out), plus the expected work below, plus the lines already on the plan. They are added up per product: a loose SKU as loose cans of its finished good, a boxed SKU as packing in boxes, or in cans where the orders do not make whole boxes, because a rounded box is a figure nobody ordered. An order line that carries a remark is not added in: it is a row of its own under its product, with that order's cans and its remark, so the floor knows which cans the remark is for. The product's own row adds up the orders without a remark and is where its stock is read. Each base row is the litres still needed beyond the approved base in the tank.

Nothing is written until Print plan, so the sheet carries the orders as they stood when it was printed. A past day's plan is never touched: the server refuses to change or print it, and the screen draws it read-only without current stock.

## Expected orders

Expected work is order lines Accounts approved whose MRP check is Pending (or on hold), and TOs that are open, sent back or on hold with Accounts, at the plan's godown. A hold, and a TO with no godown, are not counted. They show in the Waiting column and start unticked. A ticked row that prints more than the confirmed orders need is stored with `for_expected` set; on paper it is an ordinary line. Prints made before the one-page screen keep the expected box they carried.
