Production is `lib/erp/screens/production.ts` (SFG batches, FG filling, packing batches, and the stock and log tabs of each stage) and `lib/erp/screens/recipes.ts`. The arithmetic is pure in `lib/erp/engines/production.ts`; QC and box ids are rules in `lib/erp/engines/trace.ts`, with the box register in `lib/erp/units.ts`. Every consuming save runs inside `inTx`, takes `lockLot`, and reads stock through the transaction.

## A batch, end to end

sequenceDiagram
  autonumber

  participant S as stock.ts
  participant DB as Postgres

  F->>DB: inTx begin

    F->>S: lockLot(tx, rm, lot, godown)
    F->>S: rmLots(tx) - stock read inside the transaction

  loop each line
    F->>DB: insert erp_sfg_lines, syncSfgEntry -> erp_sfg_entries (yield)
  end
  F->>DB: commit, erpAudit erp.sfg.create
`} />

## Changing it safely

<Steps>
<Step title="Consume only inside inTx with lockLot">
Read stock with the transaction (`rmLots(tx)`, `sfgLots(tx)`, `fgLotStock(…, tx)`) after taking the lock, and refuse with `refuse(...)`. Reading with the pool is how two saves both spend the last litre.
</Step>
<Step title="Post through the sync functions">
`syncSfgEntry`, `syncFgEntry`, `syncPackEntry` own their stage's entries; an edit calls them again rather than writing a second entry.
</Step>
<Step title="Keep the lot codes">
`12…`, `FG12NA`, `FP40NA` are join keys across the ledgers and are on labels already in the godowns. New ids sit beside them.
</Step>
</Steps>

## Known gaps, with file references

| Gap | Where |
|---|---|
| Deleting an SFG line or a fill removes the consumption but leaves its output entry, so its stock is counted in both stages until corrected | `sfgBatches.actions.delete`, `fgFill.actions.delete` |
| Drum fills are never subtracted from drum availability (company-wide drums bought on purchases − drums sold) | `stock.ts` `rmLevelAvailable`, `packingUse` (`packing_type = 'Can'` only) |
