Sign-in is split the way everything in MBOS is: the **deciding** is pure (`mbos-app/src/engines/sign-in.ts`, `src/lib/services/mbos-service.ts`), the **doing** is in files that touch the keychain, SQLite and the network (`mbos-app/src/data/session.ts`, `src/lib/actions/mbos.ts`). Phone setup is the same: `engines/phone-readiness.ts` and `engines/setup-walkthrough.ts` decide, three screens draw.

## The handset flow

<Code file="mbos-app/src/data/session.ts" symbol="signInOnce" collapsed />

Points worth knowing before touching it:

- **Hand-over is checked twice** — once on the typed number before the server is asked (asking re-binds the device), and again on the account id the server returns (which settles a sign-in by email or a number written two ways).
- **Any `ApiError` stops.** A server that answered and refused is never followed by the offline path. Only `NoAnswerError` with no response at all falls back to `signInOffline`; a timeout reports `network`.
- **Storage failures are `payload`**, their own answer. They used to fall into the offline path, which succeeded against an empty database.
- **The bootstrap cursor is stored** (`pullCursor`) before the session is persisted, or the first delta asks for "everything since nothing" and wipes the expense policy the bootstrap just delivered.

The three setup screens read **one** list of five steps (`readSetupSteps` → `stepsForEntry(entry, steps)`), so a salesman sent from the gate to Keep tracking on reads the same titles. ## Changing it safely

<Steps>
<Step title="Add a refusal on the server with a new step">
Give it its own `step`, a sentence naming who can fix it, and a status. Then teach `loginStepFor` where to draw it — an unknown step falls to the banner, which is safe but rarely right.
</Step>
<Step title="Never make an unreadable fact block a day">
New readiness rows that the OS cannot answer must be `unknowable`, not `todo`. Only evidence gates.
</Step>
<Step title="Keep the gate unforgeable">
Never add a second way to construct `DayMayOpen`, and never give `checkIn` an optional token.
</Step>
</Steps>
