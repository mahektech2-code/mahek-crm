The order form is `mbos-app/app/order.tsx`. It prices and assesses the cart with `assessCart` (`mbos-app/src/data/orders.ts`), which calls the pure engines `engines/order.ts` and `engines/credit.ts`, then `saveOrder` writes `orders` + `order_lines` locally and enqueues `entityType: 'order'`. On the server `handleOrder` re-validates everything and writes the same `orders` row the CRM writes. An `op: 'update'` on an order is routed by shape: with `lines` it is an edit (`handleOrderEdit`), without them a progress update (`handleOrderProgress`).

## Changing it safely

<Steps>
<Step title="Keep the credit rule in one engine per side">
The handset's tiers live in `engines/credit.ts`; the server's refusals in `handleOrder`. If the business rule changes, change both and say in the how-it-works tab which one wins.
</Step>
<Step title="Never bind a Date">
Any new raw SQL in `handleOrder` takes ISO strings.
</Step>
<Step title="Count orders through the one list">
"Did we sell anything" is `lib/order-status.ts`; never write a status literal in a new query.
</Step>
</Steps>
