The day is written locally in `mbos-app/src/data/attendance.ts`, gated by `data/day-gate.ts`, and synced as `entityType: 'attendance'` to `handleAttendance` in `src/lib/actions/mbos.ts`. The route is a separate pipeline — `mbos-app/src/sync/trail.ts` on the phone, `POST /api/mbos/positions` on the server — because a position is one of thousands and worth nothing alone, and queuing them in the outbox ahead of a visit on a 2G link buys nothing.

## Punching in

<Code file="mbos-app/src/data/attendance.ts" symbol="checkIn" collapsed />

What to notice:

- `selfieMediaId: string` and `mayOpen: DayMayOpen` are **non-optional by type**. A screen that forgets to ask is a screen; a parameter that cannot be omitted is the rule.
- A second punch-in on the same day **appends a session** to the existing row (`op: 'update'`) rather than opening a new day. An already-open session returns `alreadyRunning` so the caller can drop the photos it just took.
- The selfie is queued against `'pending'` before the row exists, then `bindSelfie` re-parents it. Only the first punch-in used to bind, so every afternoon selfie stayed parented to a string — which the nightly orphan sweep deletes.
- `withinGeofence` is a fact sent with the mark; `regularisationRequested` travels only with a reason he typed.
- `trail.start('check-in')` — the `check-in` reason lets a phone that was demoted earlier today retry the background recorder, because the gate just walked him to the autostart switch.

### Forgotten punch-outs

<Code file="src/lib/mbos-jobs.ts" symbol="markMissedCheckouts" collapsed />

Activity first, position only where there is no activity, and the last open session is closed at the same instant and marked `autoClosed`. Without closing the session, `workedSecondsOf` read the day as still running and the verdict job skipped it for ever.

### Selfie retention

<Code file="src/lib/services/attachment-service.ts" symbol="sweepAttendanceSelfies" collapsed />

Runs from `runHourly` (not nightly — the setting is in hours and a nightly sweep would make 72 mean up to 96). It removes the bytes and keeps the row, so the day still names the id and `/api/attachments/[id]` answers 410 rather than pretending nothing was taken. Who may open one is `canReadAttendanceSelfie`: the person in it, and a holder of the `sales` grant inside `managerScope`.

<Callout kind="warn" title="timeInterval never reaches Android">
expo-location reads `timeInterval` out of persisted JSON options with a strict `as? Long`; `org.json` hands back a boxed `Integer`, so the override is dropped silently and the accuracy preset's fallback stands (about 2–3 s). `deferredUpdatesInterval` does arrive but is bypassed in the foreground. The cadence that matters is the JavaScript throttle above, with its mark in `kv` (not read back off `positions`, which empties as it uploads). Do not trust the Android field.
</Callout>

The id is `at|lat|lng`, and the server has a matching unique key. Android redelivers a deferred batch whenever the task did not complete, and with random ids one fix was once stored ninety-three times. An old APK cannot reintroduce duplicates because the server half does not depend on the build.

<Code file="mbos-app/src/sync/trail.ts" symbol="flush" collapsed />

`flush` loops until the queue is short. It used to send one batch per tick, and a drain with a fixed rate in front of a queue with none reports success all the way down while the Live map shows last night.

<DbTable name="mbos_positions" only={["id", "user_id", "at", "lat", "lng", "accuracy_m", "device_id"]} note={{

The server answers `tracking: "off"` when <Setting k="mbos.location.trackWhileWorking" /> is off (the phone stops and drops), and `no-session-yet` when nothing in the batch can be filed yet — the one answer that tells the phone to **hold** rather than delete, because its punch-in may still be in the outbox.

## Changing it safely

<Steps>
<Step title="Never make the selfie optional by a parameter">
If a business ever needs it optional, the setting must be read in `startDay` and the types widened deliberately — today the type is the rule.
</Step>
<Step title="Derive on the server">
Hours and status are always recomputed from `sessions`. Never write a figure the phone sent into a column pay is read from.
</Step>
<Step title="Keep the trail off the outbox">
Positions stay on their own endpoint and id scheme. Folding a changing value into a position's id breaks deduplication.
</Step>
</Steps>
