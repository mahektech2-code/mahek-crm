A field collection is written **locally first** — a `payments` row in the handset's SQLite, a timeline row, and an outbox item — inside one SQLite transaction. The outbox carries it to `POST /api/mbos/sync`, where `dispatchItem` routes `entityType: "payment"` to `handlePayment`, which writes a `payment_receipts` row at status `reported` plus its allocation lines in `payments`. Deposits and bounces are `op: "update"` items on the same entity, handled by `handlePaymentUpdate`.

## The handset side

<Code file="mbos-app/src/data/payments.ts" symbol="collectPayment" collapsed />

Two wire names matter more than they look. The handset sends `billIds` (it once sent `billRefs`, which the server did not read, so every collection was spread oldest-first) and `reference` (the cheque number or UTR — what accounts match the statement against). The cheque's written date goes as `instrumentDate`.

The payment is **not** queued behind the visit. A visit failing must not strand the money behind it.

## The server side

<Code file="src/lib/actions/mbos.ts" symbol="handlePayment" collapsed />

Three branches before anything is written:

| Case | Answer | Why |
|---|---|---|
| Customer not in the device user's scope | `rejected` | `scopedCustomer` — same rule as every MBOS write |
| Same id already present, reported by this user | `accepted` with the stored number | A resend after a lost answer, not a duplicate |
| Same id, someone else | `rejected` `duplicate` | Nothing written twice |
| A named bill missing or fully paid | `rejected` `bill_settled` | Money is never re-pointed silently |

<Code file="src/lib/actions/mbos.ts" symbol="handlePaymentUpdate" collapsed />

An update for a receipt that has not landed yet is a **retry**, not a rejection — the create is still in flight.

## Changing it safely

<Steps>
<Step title="Add a field to a collection">
Add it to `collectPayment`'s payload **and** `paymentSchema`. A key the schema does not name is dropped by the parse in silence — the bounce reason is the standing example.
</Step>
<Step title="Never bind a Date">
`receivedAt` is a date string; pass `.toISOString()` for any instant in raw SQL.
</Step>
<Step title="Keep allocation in one place">
Use `allocate` from `src/lib/engines/allocation.ts`; do not re-spread money in the handler.
</Step>
<Step title="Run the suites">
`npm run test` (mbos-app engines) and `npm run test:integration` for the dispatcher.
</Step>
</Steps>

## Known gaps

| Gap | Where |
|---|---|
| Bounce reason is not on the wire and not stored at the office | `markBounced` / `paymentUpdateSchema` |
| Handset fallback SLA (36 h) differs from the registry default | `collectPayment`, `cashInHand` |
| Manager-notify threshold 0 means "off" on the phone, "always" on the server | `collectPayment` vs `handlePayment` |
| A deposit or bounce update is accepted against a receipt in any status, including one accounts have already rejected | `handlePaymentUpdate` |
